# 一致性审查验收清单

## 基线建立检查
- [ ] Git commit ID已锁定并记录在报告中
- [ ] 前端依赖版本快照已生成（package.json）
- [ ] 后端依赖版本快照已生成（requirements.txt）
- [ ] 数据库DDL完整快照已导出（包含所有表、索引、约束）
- [ ] 环境变量配置已收集（.env.example关键配置项）
- [ ] API接口文档已从FastAPI OpenAPI schema提取
- [ ] 《一致性审查清单》模板已创建，涵盖12大维度

## 数据库层一致性检查
- [ ] 所有ORM模型表的字段名称与数据库表完全一致
- [ ] 所有字段类型映射正确（Python类型↔DB类型）
- [ ] 默认值定义在ORM和DB层一致
- [ ] 主键、外键、唯一约束、非空约束完整且合理
- [ ] 索引定义无冗余（无重复索引、无用索引）
- [ ] 枚举类型（Gender, UserRole, UserStatus, LessonPlanStatus, NotificationType等）在三层中定义一致
- [ ] 所有表都有created_at和updated_at时间戳字段
- [ ] 表命名符合规范（小写+下划线分隔）
- [ ] 《数据库差异报告》已生成，所有差异项有修复SQL

## 后端API层完整性检查
- [ ] 所有Controller路由已提取并与前端服务层比对
- [ ] 孤立接口（后端有但前端未调用）已识别并列出
- [ ] 缺失接口（前端调用但后端未实现）已识别并列出
- [ ] 所有接口URL路径与前端调用路径完全匹配（包括前缀/api/v1）
- [ ] HTTP方法（GET/POST/PUT/DELETE）在前后端一致
- [ ] 请求参数名称、类型、必填项前后端一致
- [ ] 响应格式和字段命名前后端对齐
- [ ] 错误码使用统一的ErrorCode枚举
- [ ] 错误消息在同类异常中保持一致
- [ ] 《后端冗余清单》和《缺失功能清单》已输出

## 后端代码质量检查
- [ ] 事务范围合理（无过长事务，写操作有事务保护）
- [ ] 权限注解完整（敏感操作有权限检查）
- [ ] 日志埋点规范（request_id传递、日志级别正确）
- [ ] 缓存注解使用正确（Key命名规范、失效策略合理）
- [ ] 无无效导入（import了但未使用的模块）
- [ ] 无废弃配置（注释掉的代码或过时配置）
- [ ] 无死代码（不可达的分支、未调用的方法）
